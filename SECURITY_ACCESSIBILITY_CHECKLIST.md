# StudentHub — Security & Accessibility Checklist

Mark each item only after verifying it in the running project.

## Security

- [ ] Passwords are stored using `password_hash()`; no plain-text passwords are stored.
- [ ] Login uses `password_verify()`.
- [ ] Session ID is regenerated after successful login.
- [ ] Logout clears session data and expires the session cookie.
- [ ] Protected pages validate login state on the server.
- [ ] Admin pages validate the user's role on the server.
- [ ] Session inactivity timeout is enforced.
- [ ] Database queries use prepared statements.
- [ ] Server-side validation is applied to every submitted form.
- [ ] Output from users/database is escaped with `htmlspecialchars()` before HTML rendering.
- [ ] State-changing forms use CSRF tokens.
- [ ] File uploads validate MIME type and size on the server.
- [ ] Upload filenames are generated by the application.
- [ ] Uploaded files are not executable scripts.
- [ ] Errors do not reveal database credentials, SQL, stack traces, or private paths.
- [ ] No credentials, tokens, or real private student data are committed to GitHub.
- [ ] Test/admin accounts use non-sensitive test data.
- [ ] Diagnostic pages are removed or restricted before public deployment.

## Accessibility and responsive design

- [ ] Each form control has a visible label.
- [ ] Images have meaningful alternative text, or empty alt text if decorative.
- [ ] Interactive controls are reachable by keyboard.
- [ ] Keyboard focus is visible.
- [ ] Text and background have sufficient contrast.
- [ ] Headings follow a logical hierarchy.
- [ ] Links and buttons have clear names.
- [ ] Error messages explain what needs correction.
- [ ] Status messages are not communicated by color alone.
- [ ] Pages remain usable at narrow mobile widths.
- [ ] Content does not require horizontal scrolling at common viewport widths, except wide data tables where necessary.
- [ ] Tables have clear headers.
- [ ] JavaScript-dependent actions fail gracefully when possible.
